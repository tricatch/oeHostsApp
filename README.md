# oeHostsApp

hosts 프로필을 적용해 Chrome을 실행하고, 도메인을 로컬·개발 서버로 연결하고, 오가는 요청을 확인하는 데스크톱 앱입니다.

- Windows·macOS·Linux 모두 같은 jar 파일 하나로 실행됩니다.
- OS의 hosts 파일은 건드리지 않습니다. Chrome을 실행할 때 선택한 프로필을 적용합니다.

## 주요 기능

- **oeHosts** — hosts 프로필을 만들고 폴더로 정리합니다. 여러 프로필을 함께 켜서 Chrome을 실행할 수 있고, 같은 설정을 휴대폰이나 Java 애플리케이션에도 적용할 수 있습니다.
- **oeProxy** — 도메인·경로별로 어느 서버로 보낼지 YAML로 설정합니다. 앱에 포함된 [oe-proxy](https://github.com/tricatch/oeProxy)가 443 포트에서 HTTPS 요청을 처리합니다.
- **Network** — 프록시를 거치는 요청과 응답을 실시간으로 보여 줍니다. **SSL 프록시**를 쓰면 지정한 도메인의 HTTPS 내용도 볼 수 있습니다.
- **AI 도구** — Claude Code 같은 AI 코딩 도구가 MCP나 CLI로 호스트 설정, 프록시 상태, 요청 기록을 조회할 수 있습니다.
- **가져오기 · 내보내기** — 백업 ZIP과 프로필 파일을 가져오거나 내보낼 수 있고, SwitchHosts에 등록한 hosts도 가져올 수 있습니다.

## 설치

**Java 21 이상**과 **Google Chrome**이 필요합니다.
Java는 macOS에서 `brew install openjdk`, Windows에서 `winget install EclipseAdoptium.Temurin.21.JRE`로 설치할 수 있습니다.

**macOS · Linux**

```sh
curl -fsSL https://raw.githubusercontent.com/tricatch/oeHostsApp/master/install.sh | sh
oehostsapp
```

**Windows** (PowerShell)

```powershell
irm https://raw.githubusercontent.com/tricatch/oeHostsApp/master/install.ps1 | iex
```

- 설치하면 macOS는 응용 프로그램 폴더, Linux는 앱 메뉴, Windows는 시작 메뉴에서 실행할 수 있습니다.
- 삭제하려면 macOS·Linux는 설치 명령 끝에 `| sh -s -- --uninstall`을 붙여 실행하고, Windows는 설정 → 앱에서 제거합니다. 데이터 폴더는 지워지지 않습니다.
- 설치 스크립트 없이 [릴리스](https://github.com/tricatch/oeHostsApp/releases/latest)에서 `oehostsapp.jar`를 받아 `java -jar oehostsapp.jar`로 실행해도 됩니다. 데이터 폴더를 따로 쓰려면 `--data <폴더>`를 붙입니다.

**업데이트** — 새 버전이 나오면 상단 바의 톱니바퀴 왼쪽에 업데이트 버튼이 나타납니다. 버튼을 누른 뒤 **업데이트**를 누르면 새 버전을 받아 다시 실행합니다. 데이터는 그대로 유지됩니다. 회사망 등에서 GitHub에 접속할 수 없을 때는 설치 명령을 다시 실행하면 됩니다.

## 빠른 시작

`dev.example.com`을 로컬 개발 서버로 연결해 Chrome에서 열어 보는 예시입니다.

1. **CA 인증서 등록** — 설정 → oeProxy → CA 인증서에서 인증서를 등록합니다. 처음 한 번만 하면 됩니다.
2. **vhost 추가** — oeProxy 탭에서 **+** 를 눌러 vhost를 추가하고, 도메인과 연결할 서버 주소를 적은 뒤 스위치를 켭니다.
3. **hosts 프로필 추가** — oeHosts 탭에서 **+** 를 눌러 프로필을 추가하고, `127.0.0.1 dev.example.com`을 적은 뒤 스위치를 켭니다.
4. **Chrome 실행** — oeHosts 탭 오른쪽의 **Chrome 실행**을 누르고 `https://dev.example.com`에 접속합니다.
5. **요청 확인** — Network 탭에서 요청과 응답을 확인합니다.

## 사용법

### oeHosts — 프로필로 Chrome 실행

- 프로필에는 `IP 도메인`을 한 줄에 하나씩 적습니다. 입력하면 자동으로 저장됩니다.
- 여러 프로필을 함께 켤 수 있습니다. 같은 도메인이 여러 프로필에 있으면 목록에서 위에 있는 프로필이 우선합니다.
- 오른쪽에서 Chrome 옵션(`--incognito`, `--user-agent`, `--user-data-dir`, 시작 URL 등)을 고른 뒤 **Chrome 실행**을 누릅니다. **Win / Mac** 버튼을 누르면 같은 내용을 터미널에서 실행할 수 있는 명령어로 보여 줍니다.
- 같은 Chrome 프로필이 이미 실행 중이면, 확인을 받은 뒤 기존 창을 닫고 새로 실행합니다. **저장하지 않은 작업은 사라질 수 있으니 주의하세요.**
- 목록 위의 돋보기 버튼으로 모든 프로필을 검색할 수 있고, 편집기에서는 Ctrl+F(macOS는 Cmd+F)로 찾을 수 있습니다.

**`--proxy-server` 옵션** — 이 옵션을 켜고 실행하면 Chrome이 앱의 프록시(`36980` 포트)를 거칩니다. 프로필에 적은 도메인은 지정한 IP로, 나머지는 원래대로 연결되고, 오가는 요청을 Network 탭에서 확인할 수 있습니다.

### 휴대폰에서 쓰기

휴대폰의 Wi-Fi 프록시를 이 PC로 지정하면, 휴대폰 브라우저에서도 PC의 Chrome과 같은 설정(선택한 프로필, vhost)이 적용됩니다.

1. 설정 → oeProxy → **CA 인증서** 화면 아래쪽의 **모바일 기기 인증서 설치**에서 PC 주소, QR 코드, 프록시 서버와 포트를 확인합니다.
2. 휴대폰을 PC와 같은 Wi-Fi에 연결하고, Wi-Fi 설정에서 프록시를 "수동"으로 바꾼 뒤 서버와 포트를 입력합니다.
3. PC에 접속 요청 창이 뜨면 **허용**을 누릅니다.
4. 휴대폰 카메라로 QR 코드를 찍어 인증서 페이지를 열고, CA 인증서를 설치한 뒤 신뢰하도록 설정합니다. 기기별 방법은 그 페이지에 나와 있습니다.

다 쓴 뒤에는 휴대폰의 Wi-Fi 프록시 설정을 "끔"으로 되돌려 두세요.

> ⚠️ 다른 기기가 처음 접속하면 PC에서 허용할지 묻습니다. 허용한 기기는 이 PC와 같은 네트워크에 있는 서비스에 접속할 수 있으므로, 모르는 기기는 허용하지 마세요.

### oeHosts — 다른 도구와 함께 쓰기

| 방법 | 설정 위치 | 설명 |
|---|---|---|
| 프로필 공유 URL | 편집기 위 **공유** 버튼 | 원격 hosts를 지원하는 hosts 관리 프로그램에 프로필 하나를 URL로 등록할 수 있습니다. URL에 서명이 들어 있어 주소를 추측해서 받을 수는 없습니다. |
| Active-Hosts URL | 설정 → oeHosts → Active-Hosts 공유 | 지금 켜져 있는 프로필을 합친 내용을 URL 하나로 제공합니다. oeHosts에서 선택만 바꾸면 이 URL을 쓰는 도구에 모두 반영됩니다. |
| Java 에이전트 | 설정 → oeHosts → Java 에이전트 | **옵션 복사**로 복사한 `-javaagent:...` 옵션을 JVM 옵션에 추가하면, 그 Java 애플리케이션에만 선택한 프로필이 적용됩니다. JDK 8·11·17·18 이상을 지원하며, 선택을 바꾸면 1~2분 안에 반영됩니다. |

### oeProxy — 도메인을 서버로 연결

1. **+** 를 눌러 vhost를 추가하고, 도메인과 경로별로 연결할 서버를 YAML로 적습니다. 새 vhost에는 예시가 들어 있습니다.
2. 스위치를 켜면 바로 적용되고, 오른쪽 ROUTES에서 전체 설정을 확인할 수 있습니다.
3. 브라우저가 그 도메인을 이 PC로 보내도록 oeHosts 프로필에 `127.0.0.1 도메인`을 추가합니다.

기본 설정에서는 같은 네트워크의 다른 기기도 접속할 수 있습니다(`0.0.0.0:443`). 이 PC에서만 쓰려면 설정 → oeProxy → 리버스 프록시에서 **127.0.0.1**을 선택하세요.

### SSL 프록시 — HTTPS 내용 보기

지정한 도메인의 HTTPS 요청을 복호화해서 Network 탭에 보여 줍니다. vhost를 따로 만들 필요는 없습니다.

1. CA 인증서를 등록합니다. 휴대폰에서 보려면 휴대폰에도 설치합니다.
2. Chrome을 `--proxy-server` 옵션으로 실행하거나, 기기의 프록시를 이 PC로 지정합니다.
3. Network 탭 위쪽의 SSL 프록시 설정 버튼(톱니 모양이 붙은 자물쇠)을 눌러 도메인을 추가하고 **적용**을 누른 뒤, 자물쇠 버튼을 눌러 켭니다. 목록에서 회색으로 표시된 요청을 우클릭해 **SSL 프록시에 추가**해도 됩니다.

- 도메인은 `api.example.com`(해당 도메인만), `*.example.com`(하위 도메인 전체), `*`(모든 도메인), `!도메인`(제외)처럼 적습니다.
- 인증서 고정(pinning)을 쓰는 앱, HTTP/2가 꼭 필요한 서비스, 클라이언트 인증서가 필요한 서버는 복호화하면 동작하지 않습니다. `!`를 붙여 제외하세요.

> ⚠️ 복호화한 도메인은 로그인 정보와 쿠키까지 모두 화면에 보입니다. 본인 기기에서, 꼭 필요한 도메인에만 사용하세요.

### Network — 요청 확인

프록시를 거친 요청이 위쪽 목록에 표시되고, 하나를 고르면 아래에서 헤더, 쿠키, 본문, WebSocket 메시지를 볼 수 있습니다. vhost로 연결된 요청과 복호화한 HTTPS는 내용까지 보이고, 그 밖의 HTTPS(회색 `CONNECT` 요청)는 도메인, 시간, 크기만 보입니다. 기록은 메모리에만 남고 파일로 저장되지 않습니다.

### AI 도구 — MCP · CLI

"api.example.test는 지금 어느 IP로 연결돼?", "왜 502가 나?" 같은 질문에 Claude Code가 앱의 상태를 직접 조회해서 답할 수 있습니다. 조회만 할 수 있고 설정을 바꾸지는 못합니다.

- **MCP** — 설정 → 일반 → **AI 도구**에서 **명령 복사**를 누르고, 터미널에 붙여 넣어 한 번 실행하면 Claude Code에 등록됩니다.
- **CLI** — `java -jar <jar 경로> help`로 같은 정보를 명령줄에서 조회할 수 있습니다(결과는 JSON). 같은 화면의 **CLI 스킬** URL을 Claude Code에 알려 주면 스킬로 설치됩니다.
- 이 PC에서만 접속할 수 있고 접근 토큰이 필요합니다. 쿠키, 인증 헤더, 토큰처럼 보이는 값은 해시값으로 바꿔서 전달합니다.

> ⚠️ 자동으로 가려지지 않는 정보(URL, 본문에 든 개인정보 등)는 그대로 AI 서비스로 전달됩니다. 요청 기록을 넘기고 싶지 않다면 AI 도구 화면에서 **Network 트래픽 제공**을 끄세요. 등록 명령에 포함된 토큰은 다른 사람과 공유하지 마세요.

### 가져오기 · 내보내기

| 대상 | 위치 |
|---|---|
| 프로필·vhost 하나 (`.oehosts`, `.oeproxy`) | 편집기 위 내보내기 버튼, 목록 위 가져오기 버튼 |
| 백업 ZIP (oeHosts·oeProxy·설정·CA 중 선택) | 설정 → 일반 → 가져오기 / 내보내기 |
| SwitchHosts의 hosts | oeHosts 탭의 가져오기 버튼, 설정 → 일반 → 가져오기 |

- 백업 ZIP을 가져올 때는 **추가**(기존 데이터 유지, 기본값)와 **덮어쓰기**(되돌릴 수 없음) 중에서 고릅니다.
- SwitchHosts에서 가져오는 방법은 두 가지입니다.
  - **SwitchHosts (이 PC)** — 이 PC에 설치된 SwitchHosts(4·5)를 자동으로 찾아 바로 가져옵니다. SwitchHosts의 파일은 읽기만 하고 수정하지 않습니다.
  - **SwitchHosts 내보낸 파일 (.json)** — SwitchHosts의 **내보내기** 기능으로 만든 파일(3·4·5 버전)을 엽니다.
  - 가져온 폴더와 프로필은 기존 목록 뒤에 같은 순서로 추가되며, 모두 꺼진 상태입니다. 원격 항목은 마지막으로 받아 둔 내용으로, 그룹은 포함된 항목을 합친 프로필 하나로 가져옵니다. 형식에 맞지 않는 줄은 지우지 않고 앞에 `#`을 붙여 주석으로 남깁니다.

## 인증서 (CA)

앱을 처음 실행하면 데이터 폴더의 `root-ca/`에 자체 서명 CA를 만들고, oeProxy는 이 CA로 도메인별 인증서를 발급합니다. 설정 → oeProxy → CA 인증서에서 등록할 수 있습니다. Windows는 버튼 하나로 등록되고, macOS 등은 명령어를 복사해 터미널에서 실행합니다. 등록한 뒤에는 브라우저를 다시 시작하세요. 이미 쓰고 있는 CA가 있다면 **CA 가져오기**로 바꿔 쓸 수 있습니다.

> ⚠️ 개인키 파일(`ca.pfx`)이 유출되면, 이 CA를 신뢰하는 기기에서는 어떤 사이트의 인증서든 위조할 수 있습니다. **절대 공유하지 마세요.** CA를 포함해 내보낸 백업 ZIP에도 이 개인키가 들어 있습니다.

## 포트와 데이터

| 서버 | 기본 주소 | 설정 위치 |
|---|---|---|
| 리버스 프록시 (oeProxy) | `0.0.0.0:443` | 설정 → oeProxy → 리버스 프록시 |
| 프록시 서비스 (공유 URL, 인증서 페이지 포함) | `0.0.0.0:36980` (다른 기기는 PC에서 허용해야 접속 가능) | 설정 → 일반 → 프록시 서비스 |
| MCP 서버 | `127.0.0.1:36981` (접근 토큰 필요) | 설정 → 일반 → AI 도구 |

모든 데이터는 `oehostsapp.json` 파일 하나에 저장되며, 저장할 때마다 이전 내용이 `.bak` 파일로 남습니다.

- Windows: `%APPDATA%\oeHostsApp\`
- macOS: `~/Library/Application Support/oeHostsApp/`
- Linux 등: `~/.config/oeHostsApp/`

## 문제 해결

| 증상 | 해결 방법 |
|---|---|
| "프록시 시작 실패" | 다른 프로그램(IIS, 이미 실행 중인 oeHostsApp 등)이 포트를 쓰고 있습니다. 그 프로그램을 종료한 뒤 해당 설정 화면에서 **다시 시작**을 누릅니다. |
| 브라우저에 인증서 경고가 뜸 | CA 인증서를 등록했는지 확인하고 브라우저를 다시 시작합니다. |
| 404 페이지 | 요청과 맞는 경로가 없습니다. vhost 스위치가 켜져 있는지, ROUTES에 경로가 있는지 확인합니다. |
| 502 / 504 페이지 | 연결할 서버에 접속하지 못했습니다. SSL 프록시로 연 도메인이라면 서버가 자체 서명이나 사내 CA 인증서를 쓰는 경우일 수 있으니, vhost로 등록해서 사용하세요. |
| SSL 프록시를 켰는데 내용이 안 보임 | 요청이 프록시를 거치는지(`--proxy-server` 옵션, 기기 프록시 설정) 확인하고, 도메인을 추가해 **적용**한 뒤 페이지를 새로 고칩니다. |
| Chrome에 새 옵션이 적용되지 않음 | 같은 Chrome 프로필이 이미 실행 중이었습니다. 확인 창에서 기존 창을 닫고 다시 실행하도록 선택합니다. |

원인을 더 자세히 보려면 `java -jar oehostsapp.jar`로 실행해 콘솔 로그를 확인하세요. 더 자세한 로그가 필요하면 `-Doehostsapp.log=debug`를 붙입니다. 설치 스크립트로 설치한 macOS·Linux에서는 `~/.oehostsapp/oehostsapp.log`에도 로그가 남습니다.

## 직접 빌드

빌드에는 JDK 25가 필요하고, 빌드한 jar는 Java 21 이상에서 실행됩니다.

```sh
./gradlew shadowJar    # build/libs/oehostsapp.jar
```

같은 상위 폴더에 `oeHostsAgent`([저장소](https://github.com/tricatch/oeHostsAgent))가 있으면 Java 에이전트를 함께 포함해 빌드합니다. 없으면 앱을 처음 실행할 때 최신 버전을 내려받습니다.
