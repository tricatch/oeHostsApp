# oeHostsApp

PC 한 대에서 **hosts 프로필로 Chrome을 띄우고**, 내장 역방향 프록시로 **도메인을 로컬·개발 서버에 연결하고**, 그 **트래픽을 들여다보는** 데스크톱 앱입니다.

- 창 하나로 실행되는 Java 앱이며, jar 파일 하나를 Windows와 macOS에서 똑같이 씁니다.
- Chrome은 앱이 직접 실행합니다.
- 계정 구분이 없는 1인용 도구입니다.

## 주요 기능

| 탭 | 하는 일 |
|---|---|
| **oeHosts** | hosts 프로필을 만들고 폴더로 정리하고, 여러 개를 골라 병합합니다. **Chrome 실행**을 누르면 고른 프로필의 `--host-resolver-rules`와 옵션으로 Chrome을 띄웁니다. 프로필을 URL로 공유해 원격 소스를 지원하는 호스트 관리 프로그램에서 구독할 수도 있습니다. |
| **oeProxy** | 가상 호스트(vhost)를 YAML로 적어 도메인·경로별로 백엔드에 연결합니다. 앱에 들어 있는 [oe-proxy](https://github.com/tricatch/oeProxy)가 https 443에서 돌며, 고른 vhost를 병합해 바로 반영합니다. |
| **Network** | 내장 프록시를 지나가는 요청·응답(헤더, 쿠키, 본문, WebSocket 프레임)을 실시간으로 보여 줍니다. |
| **설정** (우측 상단 톱니바퀴) | User-Agent·Open URL 프리셋, Active-Hosts 공유, Java 에이전트, 프록시 서비스(hosts 공유·인증서 페이지 포함), CA 인증서(모바일 기기 인증서 설치 포함), 리버스 프록시, 인터페이스(언어·글자 크기), 데이터 내보내기·가져오기, 정보, 오픈소스 목록 |

## 요구 사항

- **Java 21 이상**
  - macOS: `brew install openjdk` (Homebrew의 openjdk는 PATH에 없어도 찾아 씁니다)
  - Windows: `winget install EclipseAdoptium.Temurin.21.JRE`
  - 또는 [Adoptium](https://adoptium.net/)에서 설치
- **Google Chrome** — 앱이 찾는 위치
  - Windows: Program Files 또는 LocalAppData의 `chrome.exe`
  - macOS: `/Applications/Google Chrome.app`

## 설치

### macOS · Linux

```sh
curl -fsSL https://raw.githubusercontent.com/tricatch/oeHostsApp/master/install.sh | sh
oehostsapp    # 실행 (백그라운드로 뜨고, 로그는 ~/.oehostsapp/oehostsapp.log)
```

- 최신 릴리스의 `oehostsapp.jar`를 받아 체크섬을 확인한 뒤 `~/.oehostsapp/`에 두고, `~/.local/bin/oehostsapp` 명령을 만듭니다. `~/.local/bin`이 PATH에 없으면 추가하는 방법을 알려 줍니다.
- **macOS**: 응용 프로그램 폴더(`/Applications`, 쓰기 권한이 없으면 `~/Applications`)에 `oeHostsApp.app`도 만들어 Launchpad·Spotlight·Finder에서 실행할 수 있습니다.
- **Linux**: 앱 메뉴에 oeHostsApp 항목을 추가합니다.

| 작업 | 명령 |
|---|---|
| 업데이트 | 앱 안에서 업데이트([업데이트](#업데이트) 참고), 또는 설치 명령을 다시 실행 |
| 특정 버전 설치 | `curl … \| OEHOSTSAPP_VERSION=0.1.0 sh` |
| 삭제 | `curl -fsSL https://raw.githubusercontent.com/tricatch/oeHostsApp/master/install.sh \| sh -s -- --uninstall` |

삭제하면 명령·앱·메뉴 항목을 지우고 데이터 폴더는 남깁니다.

### Windows

PowerShell에서 실행합니다.

```powershell
irm https://raw.githubusercontent.com/tricatch/oeHostsApp/master/install.ps1 | iex
```

- 최신 릴리스의 `oehostsapp.jar`를 받아 체크섬을 확인한 뒤 `%LOCALAPPDATA%\Programs\oeHostsApp\`에 둡니다.
- 시작 메뉴에 **oeHostsApp** 바로가기를 만들고 설정 → 앱 목록에도 등록합니다. 시작 메뉴에서 실행하거나 작업 표시줄에 고정해 쓸 수 있습니다.
- 바로가기는 설치된 `javaw.exe`로 jar를 실행합니다. 서명 없는 exe는 Windows 스마트 앱 컨트롤이 막기 때문에 exe는 따로 만들지 않습니다.
- Java를 새로 설치했거나 다른 Java로 바꿨다면 설치 명령을 다시 실행하세요. 바로가기가 그 Java를 가리키게 됩니다.

| 작업 | 명령 |
|---|---|
| 업데이트 | 앱 안에서 업데이트([업데이트](#업데이트) 참고), 또는 oeHostsApp을 종료한 뒤 설치 명령을 다시 실행 |
| 특정 버전 설치 | `$env:OEHOSTSAPP_VERSION='0.1.0'; irm … \| iex` |
| 삭제 | 설정 → 앱 → oeHostsApp → 제거, 또는<br>`& ([scriptblock]::Create((irm https://raw.githubusercontent.com/tricatch/oeHostsApp/master/install.ps1))) -Uninstall` |

삭제하면 바로가기·앱 목록 항목·jar를 지우고 데이터 폴더(`%APPDATA%\oeHostsApp`)는 남깁니다.

### jar 직접 실행

[릴리스](https://github.com/tricatch/oeHostsApp/releases/latest)에서 `oehostsapp.jar`를 받아 실행합니다.

```sh
java -jar oehostsapp.jar                          # 실행
javaw -jar oehostsapp.jar                         # Windows에서 콘솔 창 없이
java -jar oehostsapp.jar --data D:\oehub-data     # 데이터 폴더를 따로 지정
java -Doehostsapp.log=debug -jar oehostsapp.jar     # 콘솔 로그를 더 자세히
```

### 업데이트

앱은 시작할 때마다 GitHub에 새 릴리스가 있는지 확인하고, 결과를 **설정 → 일반 → 정보**의 *업데이트* 줄에 보여 줍니다. 다른 화면에는 알림을 띄우지 않습니다.

- 새 버전이 있으면 **업데이트**를 누릅니다. 새 `oehostsapp.jar`를 내려받아 릴리스의 `SHA256SUMS.txt`로 확인한 뒤 앱을 종료하고, 설치된 jar를 바꿔서 다시 실행합니다. 데이터는 그대로 남습니다.
- 다시 시작하는 몇 초 동안 리버스 프록시와 프록시 서비스가 멈춥니다.
- **릴리스 노트**를 누르면 그 버전의 릴리스 페이지가 열립니다. **업데이트 확인**으로 다시 확인할 수도 있습니다.
- 앱 안에서 업데이트하려면 설치 스크립트로 설치했거나, jar가 쓰기 권한이 있는 폴더에서 `java -jar`로 실행 중이어야 합니다. 그렇지 않으면 새 버전 안내만 보여 주니 설치 명령을 다시 실행하세요.
- 업데이트 과정은 jar 옆의 `oehostsapp-update.log`에 기록됩니다.

### 실행할 때 알아 둘 점

- 데이터 폴더 하나에는 앱이 하나만 뜹니다. 이미 실행 중일 때 다시 실행하면 새 창 대신 기존 창을 앞으로 가져옵니다.
- 화면 언어는 시스템 언어를 따르며, 설정 → 일반 → 인터페이스에서 바꿀 수 있습니다.
- 같은 인터페이스 페이지에서 글자 크기를 고르면 앱 화면 전체가 같은 비율로 커지거나 작아집니다. Ctrl(macOS는 ⌘) + `+` / `-` 로 한 단계씩 바꾸고, Ctrl + `0`은 기본 크기로 돌아갑니다.
- 각 화면의 왼쪽 목록과 오른쪽 패널은 경계선을 끌어 너비를 바꿀 수 있고, 바꾼 너비는 모든 탭이 같이 씁니다.
- 창의 위치·크기와 최대화 상태를 기억했다가 다음 실행 때 그대로 엽니다. 모니터 구성이 바뀌어 저장된 위치가 화면 밖이면 기본 크기로 가운데에 엽니다.
- macOS에서는 시작 직후 잠깐 Java 아이콘이 보였다가 oe 로고로 바뀝니다.

## 빠른 시작

`dev.example.com`을 로컬 개발 서버로 연결해 Chrome에서 열어 보는 흐름입니다.

1. **CA 인증서 등록** — 설정 → oeProxy → CA 인증서에서 신뢰 저장소에 등록합니다. 처음 한 번만 하면 됩니다. ([자세히](#인증서-ca))
2. **vhost 만들기** — oeProxy 탭에서 **+** 로 vhost를 만들고 YAML에 도메인과 백엔드를 적은 뒤 스위치를 켭니다.
3. **hosts 프로필 만들기** — oeHosts 탭에서 **+** 로 프로필을 만들고 `127.0.0.1 dev.example.com`을 적은 뒤 스위치를 켭니다.
4. **Chrome 실행** — oeHosts 오른쪽의 **Chrome 실행**을 누르고 `https://dev.example.com`을 엽니다.
5. **트래픽 확인** — Network 탭에서 요청·응답을 봅니다.

## 사용법

### oeHosts — 프로필로 Chrome 실행

1. 왼쪽 목록의 **+** 로 프로필을 만들고 `IP 도메인` 형식으로 적습니다(자동 저장).
2. 쓸 프로필의 스위치를 켭니다. 여러 개를 켜면 병합되고, 같은 도메인은 먼저 나온 것이 이깁니다.
3. 오른쪽에서 Chrome 옵션(`--incognito`, `--user-agent`, `--user-data-dir`, 열 URL 등)을 고르고 **Chrome 실행**을 누릅니다.

- **Win / Mac** 버튼은 같은 실행을 터미널에 붙여 넣을 수 있는 명령으로 보여 줍니다.
- 열 URL은 `http://`, `https://`, `about:`, `chrome://`로 시작해야 합니다. 그 밖의 값(`dev.example.com`처럼 스킴이 없는 주소 등)이면 Chrome을 실행하지 않습니다.
- 같은 프로필(`--user-data-dir`이 같거나 둘 다 기본 프로필)로 Chrome이 이미 떠 있으면 새 옵션이 적용되지 않습니다. 그래서 확인을 받은 뒤 그 Chrome을 닫고 다시 실행합니다. 정상 종료가 안 되면 강제로 끝내므로 **저장하지 않은 작업은 사라질 수 있습니다.**
- 가져온 프로필에 위험한 옵션(프로그램 실행, 샌드박스 해제, 디버깅 포트 등)이 있으면 아무것도 실행하지 않습니다.

#### 프록시 서비스로 실행 (`--proxy-server`)

**--proxy-server**를 켜면 Chrome이 앱에 내장된 프록시 서비스(`127.0.0.1:36980`)를 거칩니다.

- 선택한 프로필의 호스트는 기록된 IP로, 나머지는 일반 DNS로 연결됩니다.
- `--host-resolver-rules`와는 함께 쓰지 않습니다.
- 포트는 설정 → 일반 → 프록시 서비스에서 바꾸고 **다시 시작**을 누릅니다.
- PC에 연결된 모든 네트워크에서 접속할 수 있습니다(`0.0.0.0:36980`). 접속 범위를 고르는 설정과 프록시 인증은 없습니다.
- 대신 이 PC가 아닌 기기가 처음 접속하면, PC 화면에 그 기기의 **IP 주소**와 **User-Agent**를 보여 주고 **허용**·**거부**를 묻습니다.
  - 허용하기 전과 거부한 뒤의 요청은 403과 안내 문구를 받습니다. 허용한 뒤 다시 시도하면 됩니다.
  - 답한 결과는 저장되어 앱을 다시 시작해도 유지되고, 프록시 서비스 화면 오른쪽 **접속 기기**에 IP 주소·기기 이름과 함께 나옵니다. 기기별 삭제 버튼이나 **목록 지우기**(확인 후 전체 삭제)로 지우면 다음 요청부터 다시 묻습니다.
  - 이 PC에서 들어오는 요청(Chrome 런처 등)은 묻지 않습니다.
- 공유한 hosts URL, Active-Hosts URL, 휴대폰 인증서 페이지도 같은 포트에서 제공합니다(아래 참고).

> ⚠️ 허용한 기기는 이 프록시를 통해 이 PC와 그 네트워크의 서비스에 접속할 수 있습니다. 모르는 기기는 허용하지 마세요.

#### 휴대폰에서 쓰기

휴대폰은 PC처럼 hosts 파일이나 DNS를 바꿀 수 없습니다. 그래서 휴대폰의 Wi-Fi 프록시를 이 PC의 프록시 서비스로 지정하고, 도메인이 연결될 곳은 프록시 서비스가 바꿉니다. 프록시 서비스는 선택한 oeHosts 프로필에 적힌 도메인을 그 IP로 연결하고, 나머지는 일반 DNS로 연결합니다. 그 결과 휴대폰 브라우저도 PC의 Chrome과 같은 규칙(선택한 oeHosts 프로필, oeProxy 가상 호스트)을 따릅니다.

1. 설정 → oeProxy → **CA 인증서**를 열고 아래쪽 **모바일 기기 인증서 설치** 구역을 봅니다. 이 PC의 주소, QR 코드, 휴대폰에 넣을 프록시 서버·포트가 나옵니다. 주소가 여러 개면 휴대폰과 같은 네트워크의 주소를 고릅니다.
2. 휴대폰을 PC와 같은 Wi-Fi에 연결하고, Wi-Fi 설정에서 프록시를 "수동"으로 바꿔 화면의 서버와 포트를 넣습니다.
3. 휴대폰이 처음 접속하면 PC에 접속 요청 창이 뜹니다. IP 주소와 User-Agent를 확인하고 **허용**을 누릅니다.
4. 휴대폰 카메라로 QR 코드를 찍으면 인증서 페이지(`http://PC의 IP:36980/ssl`)가 열립니다. CA 인증서를 내려받아 설치하고 신뢰하도록 설정합니다. 기기별 순서는 그 페이지에 나옵니다.
   - **iPhone**: 설정 → 일반 → VPN 및 기기 관리에서 프로파일을 설치한 뒤, 설정 → 일반 → 정보 → 인증서 신뢰 설정에서 켭니다.
   - **Android**: 설정 → 보안 → 암호화 및 사용자 인증 정보 → 인증서 설치 → CA 인증서에서 파일을 고릅니다(메뉴 이름은 기종마다 다릅니다).
5. 휴대폰 브라우저에서 프로필의 도메인을 엽니다.

- 인증서 페이지는 프록시 서비스가 직접 제공합니다. 휴대폰은 Wi-Fi 프록시로 지정한 그 프록시 서비스를 거쳐 이 페이지를 엽니다. 그래서 휴대폰에 프록시를 먼저 설정한 뒤 QR 코드를 찍습니다.
- 공개 인증서만 내려 주며 개인키(`ca.pfx`)는 내려 주지 않습니다.
- 처음 연결할 때 Windows 방화벽이 물으면 허용합니다.
- Android 앱은 직접 설치한 CA를 믿지 않을 수 있습니다. Chrome 같은 브라우저에서는 동작합니다.
- 다 쓰면 휴대폰의 Wi-Fi 프록시를 다시 "끔"으로 돌려 두세요.

### oeHosts — 호스트 관리 프로그램과 함께 쓰기

프록시 서비스가 프로필을 hosts 텍스트로도 제공하므로, 원격 소스를 지원하는 호스트 관리 프로그램(원격(Remote) 항목)에서 같은 프로필을 쓸 수 있습니다.

1. 프로필을 열고 편집기 위의 **공유** 버튼을 누릅니다.
2. **이 프로필 공유**를 켜고 **URL 복사**를 누릅니다.
3. 호스트 관리 프로그램에서 원격(Remote) 항목을 추가하고 URL을 붙여 넣습니다. 새로 고침 주기는 그 프로그램에서 정합니다.

공유 URL 형식:

```
http://127.0.0.1:36980/hosts/<프로필 ID>-<서명>/<프로필 이름>
```

- **서명**은 이 PC에만 있는 비밀키로 만들기 때문에 ID만 알아서는 받을 수 없습니다.
- 끝의 **이름**은 구분용(공백 등은 `_`)이라 프로필 이름을 바꿔도 예전 URL이 그대로 동작합니다.
- 공유를 켠 프로필만 제공되고, 왼쪽 목록에 공유 아이콘이 붙습니다. 공유를 끄면 그 URL은 404가 됩니다.
- 프로필을 고치면 호스트 관리 프로그램이 다음에 새로 고칠 때 반영됩니다. `${PROXY_SVR}`은 `127.0.0.1`로 바뀌어 나갑니다.
- 공유 URL은 **프록시 서비스**가 제공합니다. 포트는 설정 → 일반 → 프록시 서비스에서 바꿉니다.
  - 같은 네트워크의 다른 PC도 받을 수 있습니다. 공유 대화상자에서 URL에 쓸 **PC 주소**를 고르면 됩니다. 그 PC가 처음 받아 갈 때 이 PC에서 접속을 허용해야 합니다.

### oeHosts — 선택한 프로필을 URL 하나로 (Active-Hosts 공유)

설정 → oeHosts → **Active-Hosts 공유**에 나오는 `http://127.0.0.1:36980/active-hosts`는 oeHosts에서 지금 선택한 프로필을 합친 호스트 목록을 돌려줍니다. URL에서 hosts를 읽는 도구(Java 에이전트, 원격 소스를 지원하는 호스트 관리 프로그램 등)에 이 URL 하나를 넣어 두면, oeHosts에서 프로필 선택만 바꿔도 모든 도구가 같은 개발 환경을 따라갑니다.

- 같은 호스트가 여러 프로필에 있으면 목록에서 위에 있는 프로필이 이깁니다(프록시 서비스와 같은 규칙). 오른쪽에 지금 돌려주는 내용이 나옵니다.
- 이 URL은 프록시 서비스가 제공합니다. 기본 주소는 `127.0.0.1`(이 PC)이고, 화면에서 이 PC의 다른 주소를 고르면 같은 네트워크의 다른 PC에서도 쓸 수 있습니다(처음 접속할 때 이 PC에서 허용).
- 공유 URL과 달리 서명 토큰이 없고, 공유를 켜지 않은 프로필도 선택돼 있으면 들어갑니다. 다른 기기의 접속을 허용할 때 이 점을 생각하세요.

### oeHosts — Java 애플리케이션에 적용 (oeHosts-Agent)

oeHosts에서 선택한 프로필의 호스트를 Java 애플리케이션 하나에만 적용하는 에이전트(oeHosts-Agent)가 앱에 들어 있습니다. OS의 hosts 파일을 고치지 않고, Chrome 없이 서버·배치·테스트 같은 Java 프로그램에서 호스트를 바꿔 쓸 때 사용합니다. JDK 8, 11, 17, 18 이상에서 동작합니다.

1. 설정 → oeHosts → **Java 에이전트**에서 **옵션 복사**를 누릅니다. 프로필을 고를 필요는 없습니다.
2. 복사한 옵션을 애플리케이션의 JVM 옵션에 넣습니다.
3. oeHosts에서 적용할 프로필을 선택합니다. 선택을 바꾸면 실행 중인 애플리케이션에도 1~2분 안에 반영됩니다.

```sh
java -javaagent:<설치 폴더>/oehosts-agent.jar=http://127.0.0.1:36980/active-hosts -jar app.jar
```

- 옵션의 URL(`/active-hosts`)은 그때그때 선택된 프로필을 합친 호스트 목록을 돌려줍니다. 같은 호스트가 여러 프로필에 있으면 목록에서 위에 있는 프로필이 이깁니다(프록시 서비스와 같은 규칙). 공유를 켜지 않은 프로필도 선택돼 있으면 들어갑니다.
- 특정 프로필 하나만 쓰고 싶으면 `/active-hosts` 대신 그 프로필의 공유 URL을 넣어도 됩니다.

- Gradle은 `jvmArgs`, Maven은 `-DargLine`, IntelliJ는 실행 구성의 VM options에 같은 옵션을 넣습니다. 경로에 공백이 있으면 옵션 전체를 따옴표로 감싸서 복사합니다.
- 에이전트 파일은 앱 jar 옆의 `oehosts-agent.jar`입니다. 설치 스크립트로 설치했다면 macOS·Linux는 `~/.oehostsapp/`, Windows는 `%LOCALAPPDATA%\Programs\oeHostsApp\`입니다.
- 앱 jar에 에이전트가 들어 있어서 설치하면 바로 생깁니다(설치 스크립트가 미리 꺼내 두고, 앱도 시작할 때 확인합니다). 인터넷이 안 되는 곳에서도 쓸 수 있습니다.
- 앱은 시작할 때마다 [oeHosts-Agent 릴리스](https://github.com/tricatch/oeHostsAgent/releases)를 확인해, 더 새 버전이 있으면 내려받아 체크섬을 확인한 뒤 바꿉니다. 앱 안에 든 버전이 더 오래됐으면 이미 받은 새 버전을 되돌리지 않습니다.
- 파일 이름에 버전이 없어서, 업데이트돼도 경로가 그대로입니다. 한 번 넣은 옵션은 고치지 않아도 됩니다. 에이전트를 바꾸는 데 oeHostsApp을 다시 시작할 필요는 없지만, 실행 중인 Java 애플리케이션은 다시 시작해야 새 버전을 씁니다.
- Windows에서 그 에이전트로 실행 중인 Java 애플리케이션이 있으면 파일이 잠겨 있어 바꾸지 못합니다. 이때는 이전 버전을 계속 쓰고, 그 애플리케이션을 닫은 뒤 oeHostsApp을 다시 시작하면 바뀝니다. 설정 화면에 안내가 나옵니다.
- 애플리케이션이 시작될 때 프록시 서비스가 실행 중이어야 합니다. 에이전트는 60초마다 호스트 목록을 다시 받습니다. 받지 못하면 직전 매핑을 계속 쓰고, 처음부터 받지 못했으면 매핑 없이 실행합니다. 애플리케이션을 멈추지는 않습니다.

### oeProxy — 도메인을 백엔드로 연결

1. **+** 로 vhost를 만들고 YAML로 도메인과 경로별 백엔드를 적습니다. 새 vhost에는 예시가 들어 있습니다.
2. 쓸 vhost의 스위치를 켜면 오른쪽 ROUTES에 병합 결과가 보이고, 다음 요청부터 반영됩니다.
3. 브라우저가 그 도메인을 이 PC로 보내도록 oeHosts 프로필이나 OS hosts에 `127.0.0.1 도메인`을 넣습니다.

- 처음 한 번은 CA 인증서를 신뢰 저장소에 등록해야 브라우저 경고가 사라집니다. → [인증서 (CA)](#인증서-ca)
- 어디서 온 요청이든 모든 요청에 고른 vhost의 라우팅이 적용됩니다.
- 백엔드는 내부망과 외부 주소를 모두 허용하고, 백엔드의 내부 인증서도 신뢰합니다.
- 리버스 프록시는 **기본으로 같은 네트워크의 다른 기기도 접속할 수 있습니다**(`0.0.0.0:443`).
  - 휴대폰 등에서 쓰려면 처음 443 포트를 열 때 Windows 방화벽이 묻는 창에서 허용합니다.
  - 접속 범위는 설정 → oeProxy → 리버스 프록시의 **PC 주소**에서 고르고 **다시 시작**을 누릅니다. **이 PC에서만 접속 (127.0.0.1)**, 랜카드 주소 하나, **모든 네트워크 (0.0.0.0)** 중에서 고릅니다.
  - 랜카드 주소를 골라도 `127.0.0.1:443`은 함께 열려 있습니다. hosts 프로필의 `127.0.0.1 도메인` 줄은 그대로 동작합니다.
  - 같은 화면 오른쪽의 **접속 주소**에 지금 접속할 수 있는 주소가 모두 나옵니다.

### Network — 트래픽 보기

- oeProxy를 지나가는 요청이 위쪽 표에 쌓이고, 하나를 고르면 아래에서 헤더·쿠키·요청·응답·WebSocket·이벤트를 볼 수 있습니다.
- 상단 바 가운데 버튼으로 **캡처 시작/중지**, **지우기**를 합니다. 캡처를 멈추면 프록시도 이벤트를 만들지 않습니다.
- 고른 vhost가 없으면 프록시가 비활성이라는 안내가 나옵니다.

## 인증서 (CA)

oeProxy가 HTTPS 도메인을 처리하려면 브라우저가 앱의 CA를 신뢰해야 합니다.

- 처음 실행할 때 데이터 폴더의 `root-ca/`에 자체 서명 CA(`ca.cer` 인증서, `ca.pfx` 개인키)를 만듭니다. oeProxy는 이 CA로 도메인별 HTTPS 인증서를 발급합니다.
- 설정 → oeProxy → CA 인증서에서 등록 여부를 확인합니다.
  - **Windows**: **신뢰 저장소에 등록** 버튼으로 현재 사용자 저장소에 바로 등록합니다. 관리자 권한은 필요 없고 확인 창이 뜹니다.
  - **macOS 등**: **등록 명령어 복사**를 누르고 터미널에 붙여 넣습니다.
- 등록한 뒤에는 브라우저를 다시 시작합니다.
- 이미 쓰던 CA가 있으면 **CA 가져오기**로 바꿔 쓸 수 있습니다. 브라우저가 이미 그 CA를 신뢰한다면 다시 등록할 필요가 없습니다. 개인키는 PEM(PKCS#8, 암호 가능) 또는 PKCS#12(.pfx/.p12)를 받습니다.

> ⚠️ `ca.pfx`가 있으면 이 CA를 신뢰하는 모든 기기에 대해 아무 사이트의 인증서나 위조할 수 있습니다. **절대 공유하지 마세요.** CA 인증서를 포함해 내보낸 백업 ZIP에도 이 개인키가 들어 있습니다.

## 포트와 접속 범위

| 서버 | 기본 주소 | 기본 접속 범위 | 바꾸는 곳 |
|---|---|---|---|
| 리버스 프록시 (oeProxy) | `0.0.0.0:443` | 같은 네트워크의 다른 기기 포함 | 설정 → oeProxy → 리버스 프록시 (443 포트는 고정, 이 PC만·랜카드 주소 하나·모든 네트워크 중 선택) |
| 프록시 서비스 (hosts 공유·Active-Hosts·인증서 페이지 포함) | `0.0.0.0:36980` | 모든 네트워크, 다른 기기는 처음 접속할 때 PC에서 허용 | 설정 → 일반 → 프록시 서비스 (포트) |

설정을 바꾼 뒤에는 해당 화면에서 **다시 시작**을 눌러야 반영됩니다. 리버스 프록시는 계정 인증이 없으므로 다른 기기 접속은 믿을 수 있는 네트워크에서만 여세요.

## 데이터

### 저장 위치

| OS | 위치 |
|---|---|
| Windows | `%APPDATA%\oeHostsApp\oehostsapp.json` |
| macOS | `~/Library/Application Support/oeHostsApp/oehostsapp.json` |
| 그 밖 | `~/.config/oeHostsApp/oehostsapp.json` |

- 프로필·vhost·옵션·설정이 모두 이 파일 하나에 저장되고, 저장할 때마다 이전 내용은 `oehostsapp.json.bak`으로 남습니다.
- CA 인증서는 같은 폴더의 `root-ca/`에 있습니다.
- 데이터 폴더에 파일이 없으면 빈 상태로 시작합니다. `--data`로 다른 폴더를 지정할 때도 마찬가지입니다.

### 내보내기 · 가져오기

| 무엇을 | 어디서 | 형식 |
|---|---|---|
| 프로필·vhost 하나 | 편집기 위 내보내기 버튼 / 목록 머리의 가져오기 버튼(+ 옆) | `.oehosts` · `.oeproxy` (편집기 내용 그대로) |
| oeHosts·oeProxy·설정·CA 인증서 중 체크한 것 | 설정 → 일반 → 데이터 | 백업 ZIP 하나 |

**파일 하나씩 가져오기**

- 여러 개를 한 번에 고를 수 있고, 이름은 파일 이름을 따릅니다(겹치면 ` (2)`처럼 번호가 붙음).
- 형식이 맞지 않는 `.oeproxy`는 건너뜁니다.

**백업 ZIP**

- 데이터 화면에서 항목(oeHosts, oeProxy, 설정, CA 인증서)을 체크한 뒤 내보내기·가져오기를 누릅니다.
- 가져오기는 체크한 항목 중 파일에 있는 것만 처리하고, 체크하지 않은 항목은 건드리지 않습니다.
- 가져올 때 방식을 고릅니다.

| 방식 | 동작 |
|---|---|
| **추가** (기본) | 지금 데이터는 그대로 두고 파일의 프로필·vhost를 더합니다. 이름이 겹치면 ` (2)`처럼 번호가 붙고, 폴더는 이름으로 맞춥니다. 설정은 없는 프리셋만 더하고 나머지는 그대로 둡니다. |
| **덮어쓰기** | 해당 항목을 지우고 파일 내용으로 바꿉니다. **되돌릴 수 없습니다.** |

CA 인증서는 하나뿐이라 어느 방식이든 덮어씁니다.

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| oeProxy 아래에 "프록시 시작 실패" | 마우스를 올리면 이유가 나옵니다. 대부분 443 포트를 다른 프로그램(이미 실행 중인 다른 oeHostsApp, IIS 등)이 쓰는 경우입니다. 그 프로그램을 끄고 설정 → oeProxy → 리버스 프록시에서 **다시 시작**합니다. |
| 브라우저 인증서 경고 | CA를 신뢰 저장소에 등록했는지 확인합니다. 등록 후에는 브라우저를 다시 시작합니다. |
| 404 페이지 | 맞는 라우트가 없습니다. vhost 스위치와 ROUTES를 확인합니다. |
| 502 / 504 페이지 | 백엔드에 연결하지 못했습니다. |
| 호스트 관리 프로그램이 공유 URL을 못 받음 | 설정 → 일반 → 프록시 서비스의 상태를 확인합니다. "시작 실패"면 다른 프로그램이 포트를 쓰는 경우이니 포트를 바꿔 **다시 시작**하고 URL을 다시 복사합니다. 404면 그 프로필의 공유가 꺼져 있습니다. 다른 PC에서 받는데 403이면 이 PC의 접속 요청 창에서 허용했는지 확인합니다. |
| Chrome이 새 옵션 없이 뜸 | 같은 프로필의 Chrome이 이미 떠 있던 경우입니다. 앱이 묻는 확인에서 닫고 다시 실행을 고릅니다. |
| 업데이트가 실패하거나 다시 실행되지 않음 | 정보 화면의 오류 내용과 jar 옆의 `oehostsapp-update.log`를 확인합니다. 회사망처럼 GitHub에 접속할 수 없는 곳에서는 확인도 실패합니다. 이때는 설치 명령을 다시 실행해 업데이트합니다. 교체에 실패하면 원래 버전으로 다시 실행됩니다. |

원인을 더 자세히 보려면 `java -jar oehostsapp.jar`(필요하면 `-Doehostsapp.log=debug`)로 실행해 콘솔 로그를 확인하세요. 404·502·504가 났을 때의 라우트 목록과 원인이 나옵니다. 설치 스크립트로 설치한 macOS·Linux에서는 `~/.oehostsapp/oehostsapp.log`에 로그가 남습니다.

## 직접 빌드

JDK 25가 필요합니다. 만들어진 jar는 Java 21 이상에서 실행됩니다.

```sh
./gradlew shadowJar    # build/libs/oehostsapp.jar
```

oeHosts-Agent는 옆 폴더 `../oeHostsAgent`([저장소](https://github.com/tricatch/oeHostsAgent))에서 함께 빌드해 jar 안에 넣습니다. 그 폴더가 없으면 에이전트 없이 빌드되고, 앱이 처음 시작할 때 최신 릴리스를 내려받습니다.

## 오픈소스 · 라이선스

- 함께 들어 있는 라이브러리와 라이선스는 앱의 설정 → 일반 → 오픈 소스에서 볼 수 있고, 각 라이선스 전문은 jar 안의 `META-INF/licenses/`에 있습니다.
- oeHostsApp은 [MIT](LICENSE) 라이선스로 배포됩니다.
